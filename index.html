口径定义与版本说明

全局字段、输入规则、启用冲突、路由切换统一以本抽屉内最新口径为准
📋 监控列表（页级独立口径）
  1. 筛选栏：5 个筛选项，分别是监控编号、币对、状态、统计时间间隔、创建/编辑时间。监控编号是搜索框，输入编号的一部分就能模糊匹配（比如输 S-0 能搜到 S-001）；其他筛选项留空表示不限制。同时选多个筛选项时，只显示同时满足所有条件的记录。改任一个筛选项，下面的列表立刻自动刷新，不需要点查询按钮。
  2. 状态：每条监控只有一种状态，要么「运行中」（绿点），要么「待启用」（灰点），不会同时是两种。
  3. 创建/编辑时间：这条监控最近一次被改动的时间。会刷新这个时间的操作有：新建、编辑后保存、启用、停用。只是打开看一眼不会刷新。格式：2026-10-10 10:38:22。
  4. 最新启用时间：这条监控最近一次成功启用的时间。如果当前是待启用，或者从来没启用过，就显示 --。
  5. 最新统计时间：当前正在统计的这个固定时间窗口的结束时间。只有运行中的监控才会有值；待启用的监控显示 --。
  6. 统计时间间隔（怎么算）：改成固定时间窗口，窗口长度就是配置的 N 分钟（比如填 5 就是 5 分钟一个窗口）。窗口首尾相接、不重叠，具体规则：
    第一个窗口：开始时间 = 监控初始化时间（也就是启用时间），结束时间 = 初始化时间 + N 分钟。
    第二个及以后的窗口：开始时间 = 上一个窗口的结束时间 + 0.001 毫秒，结束时间 = 开始时间 + N 分钟。
    每个窗口内：把这个窗口时间段里、同一个方向的成交额全部加起来，看是否大于等于这个方向填的阈值。达到阈值就触发报警。
    买入和卖出各算各的，互不影响。同一个窗口内同一个方向只会触发一次报警。
  7. 买入 / 卖出阈值列：这一列分两行显示，第一行是买入方向，第二行是卖出方向。每行格式是「交易类型：金额」，比如「被动买入：120,000.00」「主动卖出：100,000.00」。交易类型来自配置表单里选的下拉框（全部交易 / 主动买入 / 被动买入 / 主动卖出 / 被动卖出）。买入用绿色，卖出用红色。
  8. 币对占用互斥：同一个市场的同一个币对，同一时间只能被一条监控占用。比如「合约 BTCUSDT」已经被 S-003 占用着，其他监控就不能再选这个币对去启用。
  9. 点「启用」：先检查这个币对有没有被别的监控占着。如果占着了，弹红条提示，红条上的文字是：「合约BTCUSDT已在监控名：BTC 冲击监控，监控编号S-003中已被监控」（格式：{市场}{币对}已在监控名：{监控名}，监控编号{监控编号}中已被监控）。状态保持不变。如果没被占，状态变成运行中，更新最新启用时间和创建/编辑时间。
  10. 点「停用」：不做任何检查，直接释放币对占用，状态变成待启用，最新启用时间变回 --。
  11. 点「编辑」：跳转到「新建监控 / 编辑配置表单」页面，把这条监控的配置带过去修改。
📝 新建监控 / 编辑配置表单（页级独立口径）
  1. 统计时间间隔怎么算：改成固定时间窗口，窗口长度就是这里填的 N 分钟（比如填 5 就是 5 分钟一个窗口）。窗口首尾相接、不重叠：
    第一个窗口：开始时间 = 监控初始化时间（启用时间），结束时间 = 初始化时间 + N 分钟。
    第二个及以后的窗口：开始时间 = 上一个窗口的结束时间 + 0.001 毫秒，结束时间 = 开始时间 + N 分钟。
    每个窗口内：把这个窗口时间段里、同一个方向的成交额全部加起来，看是否达到这个方向的阈值。
    买入和卖出各算各的，互不影响。
  2. 统计时间间隔怎么填：只能填整数分钟，不能填小数、不能填负数。输入时字母和符号会自动被清掉。如果填 0 或空着就回车，会清空并提示「统计时间请输入 ≥1 的整数分钟」。
  3. 买入阈值 / 卖出阈值：买入和卖出各有一个「交易类型」下拉框，决定统计哪种成交：全部交易、主动买入/卖出（默认）、被动买入/卖出。主动买入就是买方主动吃掉卖方挂的单；被动买入就是买方挂单被卖方主动吃掉；主动/被动卖出同理。选「全部交易」就是同方向的主动和被动都加在一起。当所选交易类型的累计成交额达到这个方向填的阈值，就触发这个方向的告警。买入和卖出各有各的阈值和交易类型，各自独立触发。
  4. 监控账号 UID 怎么填：只能填数字，填字母会被自动清掉。按回车添加一个 UID。如果这个 UID 已经加过了，不会重复加，并提示「该 UID 已存在」。空着回车不会添加。
  5. 排除账户 UID 怎么填：和监控账号一样，只能填数字，回车添加。被加在这里的账户，它的成交会被整笔剔除，不参与累计。
  6. 白名单和黑名单谁优先：先看黑名单（排除账户），命中就整笔剔除；再看白名单（监控账号），只有白名单里的账户成交才会被统计。如果一个账户同时在白名单和黑名单里，以黑名单为准，整笔剔除。
  7. 飞书接收群怎么填：只能填群编号或者通知链接。如果填了带空格的内容或者中文群名，不会添加，并提示「请输入群编号或通知链接，不支持群名」。
  8. 邮件收件人怎么填：必须是合法的邮箱格式，格式不对不会添加，并提示「请输入正确的邮箱地址」。同一个邮箱不会重复添加。
  9. 币对下拉里有些选项选不了：被正在运行的监控占用的币对，在下拉里是灰色的不能选，鼠标悬停会显示「已被运行中监控占用：监控编号 · 监控名」。没被占用的币对可以正常选。启用或停用某个监控后，下拉里的可选状态会跟着更新。
  10. 启用/停用配置：这一项决定保存后这条监控是运行中还是待启用。有两个单选：「启用（运行中）」和「停用（待启用）」。默认两个都不选，留空表示不指定。选了「启用」，保存后监控列表里这条的状态就是运行中；选了「停用」，保存后状态是待启用。如果留空不选，保存时不做状态判断，由保存逻辑决定默认状态。
  11. 点「保存」：所有必填字段都必须填，少填一个就不能保存，会弹红条提示，红条上的文字是：「请填写必填字段：{字段名}」（比如：请填写必填字段：买入阈值）。启用/停用配置不是必填项，可以留空。全部填对了之后，生成一个新的监控编号（比如 S-006），插到监控列表的最上面，然后自动跳回监控列表页，弹绿条提示「新建监控保存成功」。
  12. 保存时选的币对被占了：保存时会检查一遍所有选中的币对有没有被别的正在运行的监控占用。如果有，弹红条提示，红条上的文字是：「合约BTCUSDT已在监控名：BTC 冲击监控，监控编号S-003中已被监控」（格式：{市场}{币对}已在监控名：{监控名}，监控编号{监控编号}中已被监控），页面不关闭，也不保存。
🔔 触发记录（页级独立口径）
  1. 筛选栏：5 个筛选项，分别是监控编号、币对、方向、结果、触发时间。监控编号是搜索框，输入编号的一部分就能模糊匹配；其他筛选项留空表示不限制。同时选多个筛选项时，只显示同时满足所有条件的记录。改任一个筛选项，下面的列表立刻自动刷新，不需要点查询按钮。
  2. 监控UID交易数：这一栏显示的是，这次告警触发的统计时间段里，监控账号白名单里那些账户作为吃单方一共成交了多少笔（同一笔成交只算一次）。数字至少是 1。点击「N 笔」会弹出「监控报警相关交易记录」窗口，里面列出每笔成交的监控ID、用户ID（对手）、订单ID、成交价格、数量、成交金额、交易时间。
  3. 点方向列：方向列显示「主动买入」或「主动卖出」，文字可点击。点击后弹出的「监控报警相关交易记录」窗口和点「N 笔」是同一个，列出触发这次告警的所有相关成交明细（监控ID、用户ID、订单ID、成交价格、数量、成交金额、交易时间）。方向列的颜色：主动买入是绿色，主动卖出是红色。成交金额 = 成交价格 × 数量，单位 USDT，用黄色高亮。
  4. 发什么通知：飞书和邮件发的内容完全一样。标题固定是「【主动吃单监控】{币对}｜{方向}」。正文依次写：交易对、成交方向、统计区间、统计时间间隔、累计成交额、预警阈值、监控UID和对应的交易数量、最后一句提醒。
  5. 结果列怎么算：结果列是飞书和邮件两个渠道的综合结果。两个都成功 = 全部成功；有一个还在重试中、没有失败 = 进行中；只要有一个失败 = 部分失败。发送失败会自动重试 2 次。
  6. 点结果列：点击结果列的文字（全部成功 / 进行中 / 部分失败），会弹出一个详情窗口。窗口分左右两栏：飞书通知栏列出每个飞书群编号，邮件通知栏列出每个邮箱号。每个接收人下面列出每次发送的记录（第1次、第2次…）和对应的状态（成功 / 失败 / 重试中）以及发送时间。失败了几次就有几条记录。不去重，每次触发都会产生一条记录。

5. 口径与版本

开发版阅读说明 这一版口径定义只回答 4 类问题：这个字段是什么、什么情况下命中、点按钮后会发生什么、列表怎么展示
  1. 监控列表是主页面，配置、模板、历史、口径各自是独立页面，通过左侧导航切换，不混在一起。
  2. 同一个市场的同一个币对，同一时间只能被一条监控占用；不同市场的币对互不影响。
  3. 所有业务规则只在口径定义里写一遍，页面上不再写大段说明。如果规则变了，以口径定义的最新版本为准。

下面 6 张卡分别讲： ① 全局字段口径 = 每个字段是什么意思； ② 标签与输入规则 = 标签怎么展示、怎么输入； ③ 整数分钟、报错提示与黑白名单 = 分钟怎么填、报错长什么样、黑白名单谁优先； ④ 监控币对 = 币对怎么加、标签长什么样； ⑤ 币对互斥与冲突提示 = 点启用时怎么检查、冲突了报什么错； ⑥ 页面导航 = 点哪个按钮跳哪个页面。

全局字段口径定义
  1. 市场类型：每条币对自带市场类型，要么是现货，要么是合约，在币对名称里直接写出来（比如「现货 BTCUSDT」「合约 BTCUSDT」）。页面上不单独提供市场类型筛选项，避免和币对筛选重复引起误解。
  2. 现货币对 / 合约币对：每条监控自己维护一份币对清单。现货的币对显示成「现货 BTCUSDT」，合约的显示成「合约 BTCUSDT」。现货用蓝色标记，合约用橙色标记。
  3. 监控列表：每一行就是一条监控，由「市场 + 币对 + 监控名」共同确定。每行有三个按钮：启用/停用、编辑。新建监控走单独的配置表单页。
  4. 统计时间间隔：采用固定时间窗口，窗口长度就是配置的 N 分钟（比如填 5 就是 5 分钟一个窗口）。窗口首尾相接、不重叠：
    　第一个窗口：开始时间 = 监控初始化时间（启用时间），结束时间 = 初始化时间 + N 分钟。
    　第二个及以后的窗口：开始时间 = 上一个窗口的结束时间 + 0.001 毫秒，结束时间 = 开始时间 + N 分钟。
    　每个窗口内：把这个窗口时间段里、同一个方向的成交额全部加起来，达到阈值就触发报警。
    　买入和卖出各算各的，互不影响。同一个窗口内同一个方向只会告警一次。
  5. 交易类型：买入和卖出各有一个「交易类型」下拉框，用来决定统计哪种成交。买入方向可选：全部交易、主动买入（默认）、被动买入；卖出方向可选：全部交易、主动卖出（默认）、被动卖出。主动买入就是买方主动吃掉卖方挂的单；被动买入就是买方挂单被卖方主动吃掉；主动/被动卖出同理。选「全部交易」就是同方向的主动和被动都加在一起统计。
  6. 买入阈值：按上面选的交易类型，把买入方向的累计成交额加起来，达到这个数就触发告警。成交额 = 成交价格 × 成交数量，单位是 USDT。
  7. 卖出阈值：按上面选的交易类型，把卖出方向的累计成交额加起来，达到这个数就触发告警。成交额 = 成交价格 × 成交数量，单位是 USDT。
  8. 监控账号（白名单）：只有当吃单方的账户 UID 在这个名单里时，这笔成交才会被统计。不在名单里的账户成交直接忽略。
  9. 排除账户（黑名单）：在这个名单里的账户，它的成交会被整笔剔除，不参与统计。如果一个账户同时在白名单和黑名单里，以黑名单为准。
  10. 飞书接收群：告警触发后往这些飞书群发通知。可以填群编号或者通知链接。发送失败会自动重试 2 次。
  11. 邮件收件人：告警触发后往这些邮箱发邮件。邮箱格式不对的不会保存，重复的邮箱会自动去掉。邮件的标题和正文和飞书发的完全一样。
  12. 触发记录：专门用来展示历史告警的页面。每条记录包含：市场、币对、监控编号、监控名、触发时间、方向、累计成交额、阈值、统计时间间隔、飞书发送结果、邮件发送结果、最终结果。
  13. 通知模板：专门用来查看通知长什么样的页面，只能看不能改。通知的标题和正文以这里定义的为准。
  14. 创建/编辑时间：这条监控最近一次被改动的时间。会刷新这个时间的操作有：新建、编辑保存、启用、停用。只是打开看看不会刷新。格式：2026-10-10 10:38:22。
  15. 最新启用时间：这条监控最近一次成功启用的时间。如果当前是待启用，或者从来没启用过，就显示 --。
  16. 成交额怎么算：单笔成交额 = 成交价格 × 成交数量。统计区间内按方向分别加总。同一笔成交只算一次，不会重复累计。
  17. 怎么触发：任一方向的累计成交额达到阈值就触发那个方向的告警。买入和卖出各触发各的，互不影响。每次达到阈值都会产生一条触发记录并发送通知，不去重。
  18. 通知模板规则：标题固定为「【主动吃单监控】{币对}｜{方向}」。正文依次写：交易对、成交方向、统计区间、统计时间间隔、累计成交额、预警阈值、监控UID和对应的交易数量、最后一句提醒。飞书和邮件的内容完全一样。
标签与输入规则口径定义
  1. 监控账号 UID 怎么加：只能填数字，字母和符号会被自动清掉。按回车添加。空着回车不加。已经加过的 UID 不会重复加，并提示「该 UID 已存在」。
  2. 排除账户 UID 怎么加：和监控账号一样，只能填数字，回车添加。
  3. 飞书接收群怎么加：只能填群编号或者通知链接。填了带空格的内容或中文群名不会添加，并提示「请输入群编号或通知链接，不支持群名」。
  4. 邮件收件人怎么加：必须是合法的邮箱地址，格式不对不加，并提示「请输入正确的邮箱地址」。
  5. 币对标签长什么样：选了现货币对就显示「现货 BTCUSDT」，选了合约就显示「合约 BTCUSDT」。现货是蓝色，合约是橙色。
  6. 加标签的顺序：先检查填的对不对，再检查有没有重复，没问题才加上去。
  7. 怎么删标签：点标签右边的 × 直接删掉，不会弹确认框。币对标签还多一个「清空全部」按钮，一键删光。
  8. 填错了怎么办：输入时不对的字符会被自动清掉；按回车时再检查一遍，还是不对就清空并告诉你原因。
整数分钟、报错提示与黑白名单口径
  1. 统计时间间隔怎么填：只能填整数分钟，不能切换成小时或天。所有需要填统计时间的地方都一样。填 0 或空着回车，会清空并提示「统计时间请输入 ≥1 的整数分钟」。
  2. 报错提示长什么样：红色的提示条，出现在页面顶部中间，过一会自动消失。同一个错误不会连弹好几次。
  3. 币对被占了报什么错：启用和保存时的报错文案一样，红条上显示：「合约BTCUSDT已在监控名：BTC 冲击监控，监控编号S-003中已被监控」。格式是：{市场}{币对}已在监控名：{监控名}，监控编号{监控编号}中已被监控。
  4. 白名单和黑名单撞了怎么办：以黑名单为准。一个账户如果同时在白名单和黑名单里，它的成交整笔剔除，不参与统计。
  5. 启用前检查什么：先查这个币对有没有被别的监控占着。占着了就报错，红条上显示：「合约BTCUSDT已在监控名：BTC 冲击监控，监控编号S-003中已被监控」，状态不变，也不写启用时间。
  6. 成交额怎么统计：先把黑名单里的账户成交全部剔掉，再只统计白名单里账户的成交，最后按买入/卖出方向分别加总。
监控币对口径定义
  1. 怎么加币对：配置表单页「监控币对」区块顶部有两个下拉，一个选现货币对、一个选合约币对。选中后自动生成一个币对标签。
  2. 币对标签长什么样：现货显示成「现货 BTCUSDT」（蓝色），合约显示成「合约 BTCUSDT」（橙色），左边带一个颜色圆点。
  3. 重复和删除：同一个市场的同一个币对不能重复加。点标签右边的 × 直接删掉，还可以点「清空全部」一键删光。
  4. 怎么算被占用：只要有一条监控正在运行、且用了这个币对，这个币对就算被占用了。占用的判断维度是「市场 + 币对」。
  5. 启用时币对被占了：弹红条提示，红条上显示：「合约BTCUSDT已在监控名：BTC 冲击监控，监控编号S-003中已被监控」，和监控列表点启用报的错一样。格式：{市场}{币对}已在监控名：{监控名}，监控编号{监控编号}中已被监控。
币对互斥与冲突提示口径定义
  1. 什么算冲突：同一个市场的同一个币对，同一时间只能被一条监控占用。不同市场不算冲突，比如「现货 BTCUSDT」和「合约 BTCUSDT」可以同时跑。
  2. 怎么判断被占用：只要有一条监控正在运行、且用了这个币对，这个币对就算被占用了。
  3. 冲突时提示什么：启用和保存时的报错文案一样，红条上显示：「合约BTCUSDT已在监控名：BTC 冲击监控，监控编号S-003中已被监控」。格式：{市场}{币对}已在监控名：{监控名}，监控编号{监控编号}中已被监控。
  4. 提示长什么样：红色提示条，在页面顶部中间，过一会自动消失。同一个错误不会连弹好几次。
  5. 启用时冲突了怎么办：状态不变，不写启用时间，不发通知。
  6. 停用冲突吗：停用不检查，直接释放币对占用，别的监控之后可以用这个币对。
  7. 保存时选了启用：保存前先检查币对有没有被占。占了就不保存、不关闭页面，弹红条提示，红条上显示：「合约BTCUSDT已在监控名：BTC 冲击监控，监控编号S-003中已被监控」。
页面导航口径定义
  1. 一共有几个页面：5 个，从左到右依次是：监控列表、新建监控/编辑配置表单、通知模板、触发记录、口径与版本。通过左侧导航栏切换。
  2. 点「新建」：直接跳到「新建监控 / 编辑配置表单」页面，页面滚到表单顶部。
  3. 点「编辑」：跳到「新建监控 / 编辑配置表单」页面，把这条监控原来的配置带过来修改。
  4. 左侧导航：点击对应项就跳到对应页面。配置页的标题是「新建监控 / 编辑配置表单」。
